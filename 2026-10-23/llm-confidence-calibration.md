# 让 LLM 自报置信度，并不能得到经过校准的风险分数

- 收录日期：2026-10-23
- 原文日期：2026-10-20（2026-10-22 编辑）
- 作者：Amrut Joshi
- 来源：个人技术博客 / Hacker News
- 原文：[Asking LLM for confidence](https://rumple.github.io/blog/2026/10/20/asking-llm-for-confidence.html)
- 主题：Agent 评测、置信度校准、人工审核、可观测性

## 核心观点

让 LLM 输出一个类似 `0.85` 的置信度，并不意味着模型内部真的测量到了“答案有 85% 的概率正确”。这个数字和其他文本一样，是模型根据上下文逐 token 生成的合理续写；提示词措辞、模型先前生成的语气以及采样过程都可能改变它。

真正能够用于风险控制和人工审核路由的置信度，需要用同类任务的历史结果进行校准。系统应记录可观测特征、预测结果和最终是否正确，再根据这些真实结果估计某类输出的正确概率，并持续检查预测概率与实际正确率是否一致。

## 值得保留的工程启示

1. 不要直接把模型自报置信度作为自动执行、人工审核或拒答的门槛。
2. 将置信度视为系统级评测问题，而不是让模型表达主观感受。
3. 使用可观测信号，例如是否检索到匹配资料、不同采样结果是否一致、任务类型、历史通过率和审核结果。
4. 保存每次预测及其最终结果，定期检查不同置信度区间的实际正确率。
5. 仅有校准还不够：一个始终输出基础正确率的系统可能是校准的，却没有区分容易任务和困难任务的能力。

## 一个可落地的实现思路

```text
Agent 输出
  → 提取可观测特征
  → 独立风险模型计算置信度
  → 根据阈值自动通过或进入人工审核
  → 收集最终结果
  → 定期重新校准风险模型
```

风险模型的输入可以包括检索覆盖率、引用验证结果、工具调用错误、多个候选答案的一致性、任务类别，以及相同条件下的历史成功率。模型生成答案和系统评估答案的职责应当分离。

## 局限性

文章主要提供概念解释和工程方法，没有给出正式实验或 benchmark。文中方案是否有效，仍取决于是否有可靠的结果标签、足够的历史样本，以及线上任务分布是否发生变化。

## 收录理由

这篇文章把一个很常见但容易被忽略的错误说得很清楚：看起来精确的概率，不等于经过测量和校准的概率。它对 Agent 评测、人工审核路由和高风险自动化系统都有直接的设计价值。
